# CutLab Feature Status

## Verified Implemented Capabilities

### Platform & Persistence
- **Platform Compatibility**: Android 9.0 Pie (`minSdk = 28`) through Android 16 (`targetSdk = 36`), `applicationId = com.aistudio.cutlab.vdfqkm`, `versionCode = 2`, `versionName = "2.0"`.
- **Project Management**: Create, open, rename, duplicate, switch Quick/Advanced editor modes without losing state, search, filter, and delete projects.
- **Persistent Schema & Safe Serialization**:
  - Versioned `ProjectDocument` JSON schema (`CURRENT_PROJECT_SCHEMA_VERSION = 3`) stored inside Room (`CutLabDatabase` v2 with `MIGRATION_1_2` adding `proxy_file_path` on `media_assets`) and DataStore studio defaults (`CutLabPreferencesRepository`).
  - `ProjectSchemaMigrator` migrates legacy `v0`/`v1` -> `v2` -> `v3` project JSON forward non-destructively, preserving existing text clips while defaulting new v3 fields (`contentType`, `renderMode`, `timedWords`, `karaokeMode`, `invertStrength`, etc.).
  - **Future Schema Read-Only Protection (`schemaVersion > 3`)**: Editable decode APIs (`ProjectEngine.deserialize()`, `ProjectEngine.deserializeWithReport()`) throw `UnsupportedFutureSchemaException` on `schemaVersion > CURRENT_PROJECT_SCHEMA_VERSION`, keeping future schemas strictly separated from editable workflows. Read-only inspection (`ProjectEngine.openProjectJson()`, `decodeFutureSchemaReadOnlyPreview()`, `ProjectRepository.observeProjectLoadState()`) emits `UnsupportedFutureVersion` with preserved raw JSON, marks the workspace read-only (`future_schema_readonly_banner` + disabled edits/rename/mode switch), and blocks `ProjectEngine.serialize()` and all repository writes so unknown future fields cannot be stripped or overwritten on disk.
  - Per-project `Mutex` write serialization and corrupt-JSON non-overwrite protection (`decodeDocumentStrictOrNull`) prevent malformed JSON rows from being overwritten with blank timelines.

### Media Import (Zero-Permission)
- Video & Photo import via Android Photo Picker (`PickMultipleVisualMedia`); Audio, `.cube` LUT, and `.txt`/LRC lyric import via Storage Access Framework (`OpenMultipleDocuments` / `OpenDocument`).
- 64KB buffered local copies into app-private storage (`filesDir/cutlab_media/<projectId>/`) with real `MediaMetadataRetriever` + bounds-only `BitmapFactory` validation.

### Adaptive Workspace & Playback
- Adaptive Portrait & Landscape Compose editor preserving playhead, selection, zoom, and draft state across configuration changes.
- Drift-free preview playback loop anchored against elapsed `System.nanoTime()`, Jump Start/End, and rational frame stepping (`-1F` / `+1F` via `TimelineTimebase.stepFrameMillis`).
- Modular coordinator separation behind `ProjectWorkspaceViewModel` (`WorkspaceEditSession`, `WorkspaceMediaAnalysisCoordinator`, `WorkspaceAudioCoordinator`, `WorkspaceCaptionLyricCoordinator`, `WorkspaceExportCoordinator`) with type-safe flow state combination.

### Non-Destructive Timeline Engine
- **Session-Scoped Undo / Redo**: Bounded in-memory 60-step command stacks (`TimelineCommandHistory` managed by `WorkspaceEditSession`); each committed edit, undo, or redo snapshot is persisted immediately to Room (`ProjectRepository.saveDocument`). Undo/Redo does not survive full process death/reopen, and external project metadata edits (rename, FPS, aspect ratio, mode, export settings) plus deleted-asset pruning are rebased cleanly onto existing history entries.
- **Overlap Prevention + Confirmation-Gated Legacy Overlap Repair**:
  - New timeline mutations (`insertAssetAsClip`, `insertTextClipsBatch`, drag-and-drop `moveClip`, `trimClipLeft`/`trimClipRight`, `splitClipAt`, `duplicateClip`) prevent same-track overlaps and respect locked tracks strictly without silently shifting unrelated clips; multi-layering uses separate tracks ordered bottom-to-top, with `0..60ms` adjacent outgoing transition evaluation.
  - Loading or saving legacy projects does **not** silently shift overlapping clips. Instead, `TimelineEngine.inspectTrackOverlaps()` builds a `TimelineOverlapRepairReport` and `TimelineEngine.evaluateFrame()` / `MultiTrackAudioMixer` evaluate all active clips on unrepaired tracks without silent drops. From the workspace banner (`Review & Repair`), an explicit confirmation dialog displays affected track, affected clip, original timeline position, proposed destination track, and whether timing will change before applying `MOVE_TO_OVERFLOW_TRACK` (default) or `SHIFT_FORWARD_ON_TRACK`.
- **Timebase Architecture (4 Distinct Layers)**:
  - *Millisecond-based project storage*: Clip positions, trims, durations, timed word spans (`TimedTextWord`), keyframes, and markers persist as `Long` millisecond fields in `ProjectDocument` (the timeline storage model is **millisecond-based, not frame-native**).
  - *`RationalTime` & `TimelineTimebase` conversion utilities*: Half-up rounding converters (`RationalTime`, `frameToMillis`, `millisToNearestFrame`, `frameToPtsNs`, `audioFramesDelta`, `scaleSourceToTimelineMs`, `scaleTimelineToSourceMs`) prevent cumulative truncation drift.
  - *Frame-snapped editing operations*: Transport frame stepping (`-1F` / `+1F`) and Lyric Studio frame snapping quantize to the nearest project-FPS frame grid via `TimelineTimebase`, while speed edits, beat quantization, and source trim limits use rounded rational scaling; free drag/trim gestures still store `Long` milliseconds.
  - *Frame-based export timestamps*: Path B (`CustomGlVideoExporter`) iterates integer output frame indices (`0 until totalFrames`), generating exact nanosecond EGL presentation timestamps (`TimelineTimebase.frameToPtsNs`) and cumulative sample-accurate AAC audio chunk counts (`TimelineTimebase.audioFramesDelta`).

### Compositor, Effects, Unified Text & Invert Lyric GPU Pipeline
- **OpenGL ES 2.0 + GLSL Multi-Layer Pipeline**: Dedicated `GlCompositorRenderer` (ping-pong FBOs, dual `SurfaceTexture` OES video decoders, LRU image/LUT/text-mask texture caches) and `CustomGlVideoExporter` (offscreen EGL surface encoder) sharing `GlCompositorMath`, `CompositorShaders`, `CompositorEngine`, `UnifiedTextEngine`, `TextLayerBitmapRenderer`, and `AnimationEngine`.
- **Transforms, Blend Modes & SDF Masks**: `Position X/Y`, `Scale X/Y`, `Rotation`, `Anchor X/Y`, and `Opacity`; 7 GLSL blend modes (`Normal`, `Add`, `Multiply`, `Screen`, `Overlay`, `Darken`, `Lighten`); `Rectangle` (with rounded corners), `Ellipse`, and `Linear Split` SDF masks aligned between `CompositorEngine` and GLSL.
- **Adjustments, Filters, Shaders & 3D LUTs**: 8 filter presets, `Brightness`, `Contrast`, `Saturation`, `Exposure`, `Temperature`, `Tint`, `Vignette`, GLSL 9-tap `Soft Blur` (`blurRadius`), and GLSL unsharp `Sharpen`; 11 GPU shaders (`Chromatic Aberration`, `RGB Split`, `Film Grain`, `Bloom Glow`, `VHS Scanlines`, `Pixelate`, `Crisp Edge`, `Zoom Blur`, `Lens Warp`, `Halation`, `Neon Edge`); YCbCr Chroma Key + spill suppression; 7 procedural 3D LUTs + SAF `.cube` importer.
- **Adjustment Layers**: Cascading `ADJUSTMENT` tracks accumulate color grading bottom-to-top (`EffectsEngine.mergeAdjustments`), while the highest active adjustment track above a visual layer supplies the active GPU shader/LUT slot.
- **Unified Text & Word-Level Karaoke Engine**: `TEXT` clips support `TextContentType` (`TITLE`, `CAPTION`, `LYRIC`), 6 style presets, 6 animations (`None`, `Fade`, `Slide Up`, `Pop`, `Typewriter`, `Glitch`), `TimedTextWord` clip-local word spans (automatically partitioned on split and clamped on left/right trim), `KaraokeHighlightMode` (`NONE`, `ACTIVE_WORD`, `PROGRESSIVE`), configurable base/active/spoken colors & word spacing, stage-proportional font sizing (`0.068 * minDim`), and anchor-pivoted transforms across both Compose live preview and Path B `TextLayerBitmapRenderer` (with frame-invariant LRU bitmap caching).
- **Invert Lyric GPU Shader Effect (`TextRenderMode.INVERT_VIDEO`)**: Real GLSL fragment pass (`CompositorShaders.INVERT_TEXT_FRAGMENT_SHADER`) rendered inside both live preview (`GlCompositorRenderer`) and Path B export (`CustomGlVideoExporter`), sampling the composited video framebuffer and inverting RGB (`vec3(1.0) - base.rgb`) strictly inside the cached glyph mask with `0–100%` invert strength, optional edge softness, and optional pill background masking. `ExportPlanner` automatically enforces Path B whenever Invert Lyric or timed Karaoke clips exist.
- **Manual Lyric Studio (`LyricEngine`)**: Full lyric authoring & timing workflow independent of ASR — paste or import `.txt` / `[mm:ss.xx]` LRC files, edit/split/merge/reorder/delete lines, embedded audio/video waveform + beat timeline scrubbing, tap-at-playhead line and word start/end assignment, word duration & batch offset nudging, frame & beat snapping, reset timing, explicitly badged uniform word estimation (`isEstimated = true`), and single-undoable timeline batch commit.

### Offline Auto Caption, Audio, Dual-Path Export & Performance
- **On-Device Prerecorded Auto Caption (`engine/asr`)**: Offline speech transcription powered by `com.alphacephei:vosk-android:0.3.75` (`VoskSpeechRecognitionEngine`) fed by streaming 16 kHz mono PCM decoding (`PcmAudioExtractor.streamMonoPcm16kChunks` + stateful `StreamingMono16kResampler`) so long tracks never buffer full PCM in RAM. `AsrModelManager` handles explicit user-initiated model downloads (`en`, `es`, `fr`, `de`, `ja`), progress, cancellation, ZIP slip & model validation inside `filesDir/asr_models/`, and deletion — no silent downloads and no audio leaves the device. Cues support configurable line wrapping, inline transcript editing, word/segment timestamp preservation, and single-undoable timeline insertion.
- **Audio Engine**: Background `MediaExtractor` + `MediaCodec` PCM waveform/beat extraction, sample-rate-converted stereo PCM mixing (`MultiTrackAudioMixer`) with keyframed volume, fades, biquad EQ presets, echo, equal-power pan (`AudioDsp`), and `AudioTrack` 2.5s PCM mix audition (`WorkspaceAudioCoordinator`).
- **Dual-Path Export (`ExportPlanner` + `CutLabExportCoordinator`)**: Dispatches sequential un-edited/simple clips to Path A (`Media3TransformerExporter`) and routes gaps, non-unity volume, muted audio, multi-track overlays, text, karaoke, Invert Lyric, adjustment layers, transitions, blend modes, masks, shaders, LUTs, keyframes, speed ramps, or DSP effects cleanly to Path B (`CustomGlVideoExporter`), with automatic fallback and post-export MP4 container validation.
- **Optimization & Telemetry**: `DevicePerformanceMonitor` (API 29+ thermal listener with API 28 fallback, memory trim listener, GL frame timing, crash log capture, and persistent pipeline benchmark runner) + 540p proxy media workflow.

## Known Limitations & Verified Caveats
- **Live Audio Preview vs. Path B Export**: During normal timeline playback, `StudioMediaPlayer` uses 4 `ExoPlayer` instances (supporting speed, keyframed volume/fades, and muting) and does **not** run real-time `AudioDsp` FX (EQ, Echo, Stereo Pan) or reversed audio (`player.volume = 0f` when reversed). Full DSP FX and reversed audio are heard in **PCM Audition (2.5s mix preview)** and baked cleanly into **Path B Exports**.
- **Normal Text Layer Blend Mode vs. Invert Lyric**: `TextRenderMode.INVERT_VIDEO` renders directly inside the OpenGL FBO ping-pong chain in both live preview (`GlCompositorRenderer`) and Path B export (`CustomGlVideoExporter`) with full pixel parity. Standard `TextRenderMode.NORMAL` overlays render in Compose above the GL `TextureView` during live preview and via GL bitmap blending on export.
- **Path B Video Decode Throughput**: `CustomGlVideoExporter` samples video frames through `MediaMetadataRetriever` (`OPTION_CLOSEST` / `OPTION_CLOSEST_SYNC`) per output frame for broad format compatibility across arbitrary speed ramps and reverse playback, which trades decode speed for accuracy relative to Path A hardware transcoding.
- **In-Memory Undo/Redo Session**: Command history (`maxEntries = 60`) resets when closing and reopening the editor workspace; committed project snapshots remain persisted in Room.
- **Unsupported Future Schema Handling**: Projects saved with `schemaVersion > 3` open read-only; mutating actions and saves are blocked rather than round-tripping unknown keys through `kotlinx.serialization`.
- **Automatic Singing-Voice Lyric Recognition (Deferred Experimental Provider)**: Ordinary speech ASR models (Vosk) degrade on mixed singing vocals, reverb, and polyphonic music, so automatic singing transcription/forced alignment is cleanly isolated behind `LyricRecognitionProvider` (`DeferredExperimentalLyricProvider`) and visibly marked unavailable while Manual Lyric Studio provides the complete deterministic workflow.
- **Not Yet Implemented (Future Milestones)**: Automatic singing-voice lyric alignment (`LyricRecognitionProvider` backend), freeform Bezier pen masks, and on-device neural background segmentation.
