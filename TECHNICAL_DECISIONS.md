# CutLab Technical Decisions

1. **Zero-Permission Media Access + Managed Local Copies**:
   - CutLab uses `ActivityResultContracts.PickMultipleVisualMedia` (Photo Picker) for video/photos and `OpenMultipleDocuments` / `OpenDocument` (SAF) for audio and `.cube` LUT files, avoiding broad storage permissions (`READ_EXTERNAL_STORAGE`, `READ_MEDIA_*`) for Google Play policy compliance.
   - Because Photo Picker URIs are temporary by default, `MediaStorageManager` streams imported media into app-private storage (`filesDir/cutlab_media/<projectId>/`) on `Dispatchers.IO` with a 64KB buffer so projects reopen reliably across restarts.

2. **Four-Layer Timebase Over Millisecond Storage (`RationalTime` & `TimelineTimebase`)**:
   - **Millisecond-Based Project Storage**: `ProjectDocument` persists clip positions, trims, durations, keyframes, transitions, and markers as `Long` milliseconds for backward compatibility; the stored timeline model is intentionally **millisecond-based, not frame-native**.
   - **Conversion Utilities**: `RationalTime` and `TimelineTimebase` (`core/common/TimeFormatting.kt`) supply half-up conversions between milliseconds, frame indices, nanoseconds, audio sample counts, and speed-scaled spans to prevent cumulative truncation drift.
   - **Frame-Snapped Editing Operations**: Transport stepping (`-1F` / `+1F`) quantizes to `fps` via `TimelineTimebase.stepFrameMillis`, while speed changes, reverse trims, and beat placements round through `scaleSourceToTimelineMs` / `scaleTimelineToSourceMs`; free drag/trim gestures still commit `Long` millisecond timestamps.
   - **Frame-Based Export Timestamps**: Path B (`CustomGlVideoExporter`) steps integer output frame indices (`0 until totalFrames`) and drives `EGLExt.eglPresentationTimeANDROID` directly from `TimelineTimebase.frameToPtsNs(frameIdx, fps)` and AAC chunk sizing from cumulative `TimelineTimebase.audioFramesDelta`.

3. **Non-Overlapping New Edits + Confirmation-Gated Legacy Overlap Inspection & Repair**:
   - All new timeline edits (`insertAssetAsClip`, drag-and-drop `moveClip`, `trimClipLeft`/`trimClipRight`, `splitClipAt`, `duplicateClip`) keep tracks non-overlapping; multi-layer compositing and multi-track audio belong on separate tracks (`OVERLAY`, `AUDIO`, `TEXT`, `ADJUSTMENT`).
   - Rather than silently shifting overlapping legacy clips forward on load/save (which breaks A/V and beat-marker synchronization), `ProjectRepository` leaves timing untouched, runs `TimelineEngine.inspectTrackOverlaps()` to produce a `TimelineOverlapRepairReport` (affected tracks, clips, original timing, conflicting IDs, and proposed repair positions), and exposes all active clips on unrepaired tracks in both `TimelineEngine.evaluateFrame()` and `MultiTrackAudioMixer`.
   - Applying repair in `ProjectWorkspaceScreen` requires an explicit user confirmation dialog showing each affected track, affected clip, original timeline position, proposed destination track, and whether timing will change, with `MOVE_TO_OVERFLOW_TRACK` selected by default (`SHIFT_FORWARD_ON_TRACK` remains an explicit opt-in option).
   - `ExportPlanner` strictly inspects tracks for inter-clip/leading gaps (`> 0ms`), muted track clips, and non-unity clip volumes so edited timelines never accidentally route to linear sequential Path A concatenation.

4. **Versioned Schema Migration (`v0/v1 -> v2 -> v3`), Separated Editable vs. Read-Only Future-Schema Decoding, & Corrupt-JSON Safety**:
   - `CURRENT_PROJECT_SCHEMA_VERSION = 3` alongside `ProjectSchemaMigrator`, which performs stepwise non-destructive JSON upgrades (`v0/v1 -> v2 -> v3`: preserving v2 text clips while supplying defaults for `TextContentType`, `TextRenderMode`, `KaraokeHighlightMode`, `timedWords`, and Invert Lyric controls) prior to `kotlinx.serialization` decoding.
   - Because `kotlinx.serialization` with `ignoreUnknownKeys = true` drops unrecognized JSON keys upon re-serialization (which would destroy future fields such as `v4+` schemas), `ProjectEngine` strictly separates **supported editable decoding** (`deserialize()`, `deserializeWithReport()`, which throw `UnsupportedFutureSchemaException` whenever `schemaVersion > CURRENT_PROJECT_SCHEMA_VERSION`) from **read-only future preview decoding** (`openProjectJson()` returning `UnsupportedFutureVersion` / `decodeFutureSchemaReadOnlyPreview()`). `ProjectEngine.serialize()` also throws `UnsupportedFutureSchemaException` for `schemaVersion > 3`, and `ProjectRepository` blocks all writes/imports/deletes against future-schema rows, preserving original JSON intact on disk.
   - `ProjectRepository` serializes document writes per project with a `Mutex` and refuses to overwrite unparseable existing `projectJson` rows with an empty blank project.

5. **Session-Scoped Undo/Redo with Metadata Rebase & Asset Pruning**:
   - Undo/Redo stacks (`TimelineCommandHistory` inside `WorkspaceEditSession`) remain bounded (60 steps) and in-memory for fast responsive scrubbing/editing, while every committed edit, undo, or redo immediately saves the active `ProjectDocument` snapshot to Room.
   - Generating Auto Captions or committing synchronized lyrics inserts all `TEXT` clips in one batch (`insertTextClipsBatch`) so a single Undo reverts the entire batch without touching imported media or shifting unrelated clips.

6. **Shared GLSL / Pure-Kotlin Composition & Coordinator Separation**:
   - Both live GL preview (`GlCompositorRenderer` + `StudioMediaPlayer`) and Path B export (`CustomGlVideoExporter`) call `GlCompositorMath`, `CompositorShaders`, `CompositorEngine`, `AnimationEngine`, `UnifiedTextEngine`, and `TextLayerBitmapRenderer` with identical `0.068f * minDim` text scaling and clip-local `TimedTextWord` karaoke evaluation.
   - **Invert Lyric GPU Shader Pass (`TextRenderMode.INVERT_VIDEO`)**: Rather than faking inversion with Compose blend modes or alpha inversion, `GlCompositorRenderer` and `CustomGlVideoExporter` both upload a transparent white glyph mask (`TextLayerBitmapRenderer`), ping-pong the composited video FBO, and execute `CompositorShaders.INVERT_TEXT_FRAGMENT_SHADER` (`mix(base.rgb, vec3(1.0) - base.rgb, maskAlpha * uInvertStrength * uOpacity)`). `ExportPlanner` enforces Path B whenever any active clip uses `INVERT_VIDEO` or timed karaoke highlights.
   - `ProjectWorkspaceViewModel` delegates long-running analysis, PCM auditioning, ASR/lyric sync, export orchestration, and edit session state to focused coordinators (`WorkspaceEditSession`, `WorkspaceMediaAnalysisCoordinator`, `WorkspaceAudioCoordinator`, `WorkspaceCaptionLyricCoordinator`, `WorkspaceExportCoordinator`) using strongly typed state bundles.

7. **Privacy-First On-Device Prerecorded ASR (`vosk-android`) & Honest Singing-Lyric Boundary**:
   - Prerecorded-file Auto Caption uses `com.alphacephei:vosk-android:0.3.75` (`VoskSpeechRecognitionEngine`) fed by bounded chunked 16 kHz mono PCM decoding (`PcmAudioExtractor.streamMonoPcm16kChunks` + `StreamingMono16kResampler`) because Android's `SpeechRecognizer` is designed for live microphone capture rather than deterministic prerecorded-file word timestamps.
   - Audio never leaves the device. Large language models (`en`, `es`, `fr`, `de`, `ja`) are never downloaded silently; downloads require explicit user tap, display size/progress, support cancellation, and are validated and stored in `filesDir/asr_models/`.
   - Because speech ASR degrades on polyphonic singing vocals, Manual Lyric Studio (`LyricEngine`) delivers complete offline/manual `.txt`/LRC editing, tap-at-playhead sync, beat/frame snapping, and visibly labeled uniform word estimation (`isEstimated = true`), while `LyricRecognitionProvider` cleanly defers automatic singing alignment until a dedicated vocal-separation/alignment model is added.

8. **Hybrid Dual-Path Rendering Strategy & Adaptive Thermal/Memory Scaling (API 28–36)**:
   - Unmodified sequential timelines route to **Path A (`Media3TransformerExporter`)**, while composited/FX/gap/audio-mixed/karaoke/Invert Lyric timelines route to **Path B (`CustomGlVideoExporter`)**.
   - `DevicePerformanceMonitor` monitors thermal status (API 29+ with API 28 fallback) and `onTrimMemory` callbacks to downscale live preview FBOs (`100%` -> `75%` -> `50%`) and prune texture/PCM/bitmap caches without compromising full-resolution exports.
